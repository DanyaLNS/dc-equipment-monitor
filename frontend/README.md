# Frontend dc-equipment-monitor

Нужны Node.js 22 или 24, npm. Для рабочего режима нужен Backend с REST API v1 из [ТЗ](../docs/DEVELOPMENT_SPEC.md). Интерфейс использует React, TypeScript, Vite и Ant Design.

## Демо без Backend

```sh
cd frontend
npm ci
npm run demo
```

Откройте адрес из вывода Vite (обычно http://127.0.0.1:5173).

| Роль | Логин | Пароль |
| --- | --- | --- |
| ADMIN | `admin` | `demo1234` |
| OBSERVER | `observer` | `demo1234` |

У «Сервера приложений» уже есть два порта с разными состояниями и историей. Под ADMIN можно менять стойки, устройства, порты и настройки. Под OBSERVER доступны просмотры и фильтры. Данные и сессии хранятся в памяти Vite и сбрасываются после его перезапуска. TCP-результаты симулируются, сетевых проверок нет. После пяти неверных паролей заглушка временно блокирует вход на 15 секунд для демонстрации Retry-After.

## Публикация демо на GitHub Pages

Для GitHub Free нужен публичный репозиторий. После того как workflow появится в основной ветке, выберите **Settings → Pages → Build and deployment → Source → GitHub Actions**. Затем откройте **Actions → Deploy frontend demo to GitHub Pages → Run workflow**. По завершении ссылка появится в задании Deploy. Для репозитория проекта она обычно имеет вид `https://<владелец>.github.io/<репозиторий>/`.

Workflow выполняет `npm ci` и `npm run build:demo` в `frontend/`, затем публикует `frontend/dist/`. Локально статическую сборку можно проверить командами `npm run build:demo` и `npm run preview -- --mode pages`. Адреса экранов используют `#`, например `/#/equipment/1`.

Аккаунты те же, что в локальном демо. Статическое демо симулирует сессию и API в памяти вкладки. После перезагрузки данные сбрасываются и нужно заново войти. Выбранный маршрут сохраняется в адресе.

## Рабочий режим и проверки

```sh
cd frontend
npm ci
npm run dev
```

Откройте http://localhost:5173. Vite проксирует запросы `/api/v1/*` на `http://127.0.0.1:8080`, сохраняя путь, cookie и Origin. Для другого адреса Backend задайте `API_PROXY_TARGET` в `frontend/.env.local` и перезапустите Vite. Настройте Backend на приём браузерного Origin, например `http://localhost:5173`.

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run preview
```

При общем запуске раздавайте каталог `dist/` через прокси, передавайте `/api/v1/*` в Backend на том же origin без удаления префикса, а для маршрутов интерфейса используйте fallback на `index.html`. В текущей ветке конфигурации общего запуска и исполняемого Backend нет. Для локальной проверки готовой сборки `npm run preview` использует тот же API-прокси.

Демо API включается отдельной командой. Обычный dev-запуск и production-сборка используют реальный API. Для проверки на реальном Backend создайте пользователей обеих ролей его операционными командами. Под ADMIN создайте стойку, устройство и два порта, проверьте разные результаты в карточке, историю, выключение мониторинга и выход. Под OBSERVER откройте те же записи и проверьте серверный отказ на изменение. Для проверки 412 откройте одну форму в двух вкладках, сохраните изменение в первой и попробуйте сохранить черновик во второй.
