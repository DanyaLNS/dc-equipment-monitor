# Frontend dc-equipment-monitor

Нужны Node.js 22 или 24, npm и Backend с REST API v1 из [ТЗ](../docs/DEVELOPMENT_SPEC.md). Интерфейс использует React, TypeScript, Vite и Ant Design.

```sh
cd frontend
npm ci
npm run dev
```

Откройте http://localhost:5173. Vite проксирует запросы `/api/v1/*` на `http://127.0.0.1:8080`, сохраняя путь, cookie и Origin. Для другого адреса Backend задайте `API_PROXY_TARGET` в `frontend/.env.local` и перезапустите Vite. Настройте Backend на приём браузерного Origin, например `http://localhost:5173`.

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run preview
```

При общем запуске раздавайте каталог `dist/` через прокси, передавайте `/api/v1/*` в Backend на том же origin без удаления префикса, а для маршрутов интерфейса используйте fallback на `index.html`. В текущей ветке конфигурации общего запуска и исполняемого Backend нет. Для локальной проверки готовой сборки `npm run preview` использует тот же API-прокси.

Vitest подставляет ответы по контракту только внутри тестов. В рабочем режиме клиент всегда обращается к API. Для проверки на реальном Backend создайте пользователей обеих ролей его операционными командами. Под ADMIN создайте стойку, устройство и два порта, проверьте разные результаты в карточке, историю, выключение мониторинга и выход. Под OBSERVER откройте те же записи и проверьте серверный отказ на изменение. Для проверки 412 откройте одну форму в двух вкладках, сохраните изменение в первой и попробуйте сохранить черновик во второй.
